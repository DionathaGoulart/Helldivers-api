Problem types

Errors are RFC 9457 problem details, sent as application/problem+json and never cached. The type of a response links straight to its section on this page. 

{
  "type": "https://helldivers-api.dionatha.com.br/docs/errors#invalid-filter-value",
  "title": "Invalid filter value",
  "status": 400,
  "detail": "category: `primray` is not a valid value. Allowed: primary, secondary, throwable.",
  "instance": "/v1/query/weapons?category=primray"
}

Read detail — it names the parameter and the values that would work. instance is the path and query that failed. Static files (a missing item, a typo in a collection name) answer with the 404 page of the static host instead.

400 · UNKNOWN-PARAMETER

The query string carries a name the route does not define, usually a typo (?categorie=primary) or a filter that belongs to another collection.

Fix: drop the parameter. Each collection lists its filters in the reference; every route also accepts q, sort, fields, page and limit.

400 · INVALID-FILTER-VALUE

The filter exists but the value does not: a category that is not in the enum, or an id (warbond, trait, passive, armor set) that no entity has.

Fix: detail lists the allowed values for an enum, or points at the file to read for ids, for example /v1/warbonds.json. Values are the ones in the data (support_weapon, not support-weapon); only facet file names are kebab-cased.

400 · INVALID-PARAMETER

A common parameter is out of range or malformed: page below 1, limit above 100 (50 on /v1/search), an unknown sort key or fields name, a q shorter than two characters, an unknown collection in collections, or one of them repeated.

Fix: paging and sorting defaults are page=1, limit=50, sort=id. A filter may be repeated — the values are OR-ed — but q, sort, fields, page and limit may appear only once.

401 · INVALID-KEY

The request sent an Authorization header, and it is not a valid API key: not Bearer hd2_…, a key with a typo, or a key that was revoked. The response carries WWW-Authenticate: Bearer.

Fix: copy the key again, exactly as you got it. To use the anonymous limits instead, send no Authorization header at all. A lost or leaked key is replaced, not recovered — ask for a new one.

404 · NOT-FOUND

The dynamic route does not exist: an unknown collection under /v1/query/.

Fix: collection names are in /v1/meta.json. A missing static file — an item, a facet, an image URL built by hand instead of read from image.url — gets the static host's 404 page instead.

405 · METHOD-NOT-ALLOWED

The API is read-only. Only GET, HEAD and OPTIONS are answered; the response repeats them in Allow.

Fix: use GET.

429 · RATE-LIMITED

/v1/query/* and /v1/search count requests per client: anonymous clients by IP, allowlisted sites by visitor, keys by key. The detail names your limit, RateLimit-Policy repeats it and Retry-After says how many seconds to wait. Static files are never limited.

Fix: wait Retry-After seconds. For anything regular, read the static files instead — a facet, a collection or /v1/all.json once a day — and filter locally. Need more? Ask for access.

500 · INTERNAL-ERROR

Something failed inside the Worker — most often a data file that could not be read. Nothing is cached, so the next request may well succeed.

Fix: retry once. If it persists, open an issue with the instance, the time and the cf-ray header.
